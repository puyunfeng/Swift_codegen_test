# swift_codegen — 把 Kotlin sealed type 变成 Swift enum

Kotlin Multiplatform 里的 `sealed interface` 到 Swift 就退化成一堆 Kotlin 导出的类，
只能 `if let x = value as? HelloTestHelloOneFun` 一层层强转，漏掉分支编译器也不会提醒。
这个项目用一个注解 + KSP 处理器 + Gradle 插件，在构建时生成原生 Swift `enum`：
每个 sealed 子类型对应一个 case（构造参数变成关联值），并附带 `toX()` 方法把 enum
还原成 Kotlin 对象。这样 Swift 侧可以写穷尽 `switch`，漏分支直接编译不过。

## 例子

Kotlin 侧，给 sealed 类型加注解即可（注解来自 `swift_codegen_annotations`，
由插件自动加进 `commonMainImplementation`）：

```kotlin
package com.example.swift_codegen_test

import com.example.swift_codegen.GenerateSwiftEnum

@GenerateSwiftEnum
sealed interface HelloTestHello {
    object OneTab : HelloTestHello
    class OneFun(val s: String, val s2: String) : HelloTestHello
    class ThreeFun2(val s: String, val s2: Int, val s3: Boolean) : HelloTestHello
    class UserFun(val user: User) : HelloTestHello
}

data class User(val name: String)
```

执行 `./gradlew generateSwiftEnums` 后，`iosApp/iosApp/Generated/HelloTestHelloEnum.swift`：

```swift
// Generated by KSP from com.example.swift_codegen_test.HelloTestHello. Do not edit.
// Regenerate with: ./gradlew generateSwiftEnums
import SharedLogic

public enum HelloTestHelloEnum {
    case oneFun(s: String, s2: String)
    case oneTab
    case threeFun2(s: String, s2: Int32, s3: Bool)
    case userFun(user: User)

    public func toHelloTestHello() -> HelloTestHello {
        switch self {
        case let .oneFun(s, s2):
            HelloTestHelloOneFun(s: s, s2: s2)
        case .oneTab:
            HelloTestHelloOneTab.shared
        case let .threeFun2(s, s2, s3):
            HelloTestHelloThreeFun2(s: s, s2: s2, s3: s3)
        case let .userFun(user):
            HelloTestHelloUserFun(user: user)
        }
    }
}
```

Swift 侧就是一个普通 enum：`switch` 穷尽、可以自由加 `Identifiable`/`Equatable` 等协议，
需要交回共享代码时调 `toHelloTestHello()`：

```swift
struct IntentListView: View {
    let intents: [HelloTestHelloEnum]

    var body: some View {
        List(intents.indices, id: \.self) { index in
            switch intents[index] {
            case .oneTab:
                Text("tab")
            case let .oneFun(s, s2):
                Text(s + s2)
            case let .threeFun2(s, s2, s3):
                Text("\(s) \(s2) \(s3)")
            case let .userFun(user):
                Text(user.name)
            }
        }
    }
}

// 交回 Kotlin 侧的 ViewModel
func send(_ intent: HelloTestHelloEnum, to viewModel: ViewModel) {
    viewModel.onIntent(intent.toHelloTestHello())
}
```

> 生成的是单向映射（Swift enum → Kotlin 对象）。反过来把 Kotlin 实例转成 enum 没有生成，
> 需要在 Swift 里自己 `if let` 映射一次。

## 组成

| 模块 | 发布坐标 | 作用 |
| --- | --- | --- |
| `swift_codegen_annotations` | `com.example.swift_codegen:swift_codegen_annotations` | KMP 库，提供 `@GenerateSwiftEnum` 和 `GenerateSwiftEnumMode` |
| `swift-codegen` | `com.example.swift_codegen:swift_codegen` | KSP 处理器，解析注解并写 Swift 文件 |
| `swift_codegen_gradle_plugin` | `com.example.swift_codegen:swift_codegen_gradle_plugin` | Gradle 插件 `com.example.swift_codegen`，串联上面两者并注册 `generateSwiftEnums` |

生成时机：插件把处理器挂到所有 `kspIos*` 配置上，`generateSwiftEnums` 依赖第一个可用的
`kspKotlinIosSimulatorArm64` → `kspKotlinIosArm64` → `kspKotlinIosX64`。

## 集成

需要 Kotlin Multiplatform + KSP，并且至少声明一个 iOS target。本仓库的示例工程 `sharedLogic`
就是按下面这套配置接的，可以对照着看。

### 1. 配置仓库

产物发布在 GitHub Packages（`https://maven.pkg.github.com/puyunfeng/Swift_codegen_test`）。
`pluginManagement` 负责解析插件标记，`dependencyResolutionManagement` 负责解析插件自动注入的
注解与处理器依赖，两处都要加：

```kotlin
// settings.gradle.kts
pluginManagement {
    repositories {
        mavenLocal()
        maven {
            url = uri("https://maven.pkg.github.com/puyunfeng/Swift_codegen_test")
            credentials {
                username = providers.gradleProperty("gpr.user").orNull
                password = providers.gradleProperty("gpr.key").orNull
            }
        }
        google {
            mavenContent {
                includeGroupAndSubgroups("androidx")
                includeGroupAndSubgroups("com.android")
                includeGroupAndSubgroups("com.google")
            }
        }
        mavenCentral()
        gradlePluginPortal()
    }
}

dependencyResolutionManagement {
    repositories {
        mavenLocal()
        maven {
            url = uri("https://maven.pkg.github.com/puyunfeng/Swift_codegen_test")
            credentials {
                username = providers.gradleProperty("gpr.user").orNull
                password = providers.gradleProperty("gpr.key").orNull
            }
        }
        mavenCentral()
    }
}
```

放在 `google()` / `mavenCentral()` 之前即可：`google()` 已经被 `mavenContent` 限制在
androidx / com.android / com.google 三组，本来也不会去查 `com.example.swift_codegen`；
而没有配凭据时，Gradle 在这个仓库拿到 401 会继续尝试下一个仓库，不会让构建失败。

凭据放在 `~/.gradle/gradle.properties`：

```properties
gpr.user=<GitHub 用户名>
gpr.key=<read:packages 的 PAT>
```

### 2. 版本目录（推荐）

`gradle/libs.versions.toml` 里登记版本和插件别名：

```toml
[versions]
ksp = "2.3.13"          # 与 Kotlin 2.4.21 配套
swiftCodegen = "1.0.0"

[plugins]
ksp = { id = "com.google.devtools.ksp", version.ref = "ksp" }
swiftCodegen = { id = "com.example.swift_codegen", version.ref = "swiftCodegen" }
```

用别名而不是在每个模块里硬编码 `id("com.example.swift_codegen") version "1.0.0"`，
是为了让版本号集中在 `libs.versions.toml` 一处，升级时只改一行。

> 本仓库里 `gradle.properties` 的 `swiftCodegenVersion` 是这三个库**发布**用的版本，
> `libs.versions.toml` 的 `swiftCodegen` 是示例工程**消费**用的版本。示例从 mavenLocal
> 解析插件，所以两者要一致。

### 3. 应用插件

```kotlin
plugins {
    alias(libs.plugins.kotlinMultiplatform)
    alias(libs.plugins.androidMultiplatformLibrary)
    alias(libs.plugins.ksp)
    alias(libs.plugins.swiftCodegen)
}
```

KSP 版本要与 Kotlin 版本匹配（这里的 2.3.13 对 2.4.21）。与 codegen 插件的先后顺序无关：
插件内部用 `pluginManager.withPlugin` 惰性挂接，先应用哪个都生效，习惯上把 KSP 写在前面。
处理器和注解依赖由插件注入，不需要手动声明。

### 4. 声明 iOS target

生成出来的文件要 `import` 你的 framework，所以 target 与 framework 名要对得上：

```kotlin
kotlin {
    listOf(iosArm64(), iosSimulatorArm64()).forEach { target ->
        target.binaries.framework {
            baseName = "SharedLogic"   // 对应 swiftCodegen.swiftModuleName
            isStatic = true
        }
    }
}
```

### 5. 配置

```kotlin
swiftCodegen {
    // 必须等于 iOS framework 的 baseName，因为生成文件里会 `import` 它
    swiftModuleName.set("SharedLogic")
    // 相对"仓库根目录"；落在 Xcode 16 的同步文件夹里，生成后自动参与编译
    outputSubDir.set("iosApp/iosApp/Generated")
}
```

### 6. 生成并接入 Xcode

```bash
./gradlew generateSwiftEnums
```

想确认这次到底生成/跳过了什么，或者需要强制重跑：

```bash
./gradlew generateSwiftEnums --info --rerun-tasks
```

`--info` 才会显示处理器自己的日志（`[ksp] Generated <path>` /
`[ksp] Swift enum is already up to date`）。只加 `--info` 通常看不到东西：输入没变时
`kspKotlinIos*` 直接 UP-TO-DATE，处理器根本不会运行。`--rerun-tasks` 会忽略 up-to-date 检查，
代价是整条链（Kotlin/Native 编译 + KSP）都重跑，所以只用于排查，日常构建别带。

Xcode 只编译「属于 target 的文件」，而生成的 `.swift` 是 Gradle/KSP 直接写到磁盘的，
不会修改工程文件，所以要分两种情况：

- **Xcode 16+ 同步文件夹（本仓库，`objectVersion = 77`）**：`iosApp/iosApp` 是
  `PBXFileSystemSynchronizedRootGroup`，目录里有什么文件就编译什么文件。生成到
  `iosApp/iosApp/Generated` 会被自动编译，工程文件不用动。
- **老工程（用 group 逐文件登记）**：需要把生成目录加进 target 的 Compile Sources **一次**。
  建议用「文件夹引用」（Add Files 时选 Create folder references，蓝色文件夹），这样以后
  新增 `@GenerateSwiftEnum` 类型产生的新文件也会自动被编译；用「创建组」的话每多一个
  文件都要重新加一次。用 XcodeGen/Tuist 则把目录声明进 `sources` 即可。

重复生成不会破坏引用：输出路径稳定，且内容没变化时处理器不重写文件，
所以 Xcode 的增量编译不会被无意义地触发。

## 配置项

| 属性 | 默认值 | 说明 |
| --- | --- | --- |
| `swiftModuleName` | `App` | 生成文件里的 `import` 模块名，通常是 framework 的 `baseName` |
| `outputSubDir` | `iosApp/Sources/Generated` | 输出目录，相对仓库根目录 |
| `swiftEnumMode` | `CONCURRENT` | `SEQUENTIAL` / `CONCURRENT`；并发写入要求每个注解输出到不同文件 |
| `swiftEnumSuffix` | `Enum` | 未指定 `swiftEnumName` 时，枚举名 = `<接口名><后缀>` |
| `swiftFormatPath` | 空 | `swiftformat` 可执行文件路径；空则依次尝试 `PATH`、`/opt/homebrew/bin`、`/usr/local/bin`，都没有就跳过格式化 |

## 注解参数

`@GenerateSwiftEnum` 的字符串参数为空表示「沿用全局配置」。

| 参数 | 说明 |
| --- | --- |
| `swiftModuleName` | 覆盖全局模块名 |
| `outputSubDir` | 覆盖全局输出目录 |
| `swiftEnumName` | 完整的 Swift 枚举名，默认 `<接口名><swiftEnumSuffix>` |
| `mode` | 覆盖全局 `swiftEnumMode`；只有显式传值时才生效 |

case 名取子类型简单名：去掉 `Intent` 后缀、首字母小写（`OneFun` → `oneFun`），
命中 Swift 关键字时自动加反引号。

## 支持的类型

子类型必须是 `object` 或 `class`；`class` 需要主构造，参数类型限下表（其余会报错并跳过
该子类型，生成结果不完整）：

| Kotlin | Swift |
| --- | --- |
| `String` | `String` |
| `Int` / `Long` / `Short` / `Byte` | `Int32` / `Int64` / `Int16` / `Int8` |
| `Boolean` / `Double` / `Float` | `Bool` / `Double` / `Float` |
| `Char` | `Character` |
| `List<T>` / `Array<T>` / `Collection<T>` / `Iterable<T>` | `[T]` |
| `Set<T>` | `Set<T>` |
| `Map<K, V>` | `[K: V]` |
| `T?` | `T?` |
| 其它 class（含 `@ObjCName`） | 对应 Swift 名，嵌套类按外层名拼接 |

## 限制

- 只支持 sealed class/interface；枚举类子类型（`enum class`）不支持。
- 一个注解生成一个文件，文件名是 `<swiftEnumName>.swift`。
- `CONCURRENT` 模式下每个被注解类型必须写到不同文件，否则会互相覆盖。
- 生成目录必须落在 Xcode 会编译的路径下：Xcode 16+ 的同步文件夹工程（本仓库）自动生效，
  老工程需要手动加一次，见「生成并接入 Xcode」。
- 插件内部注入的注解/处理器版本与插件自身版本一致（同一次发布），升级时三者一起升级。
